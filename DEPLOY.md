# Выкатка Sonar на Render

Для того, кто проводит деплой. Порядок шагов важен: несколько значений
существуют только после того, как создан сервис, который их порождает, и
поставить их заранее нельзя.

`render.yaml` описывает четыре вещи: базу `sonar-db`, API `sonar-api`, воркер
рендера `sonar-video-worker` и фронтенд `sonar-frontend`. Blueprint создаёт их
все, но пустыми по секретам — всё, что помечено `sync: false`, вводится руками.

## Чего это стоит

Воркера на бесплатном плане у Render не бывает — видео кодируется процессором,
и бесплатные инстансы такую нагрузку не несут. `starter` это минимум, и это
единственный сервис в блюпринте, который стоит денег.

API и фронтенд на free-плане засыпают без нагрузки: первый запрос после паузы
ждёт холодный старт. Для демонстрации клиенту это плохо — поднимите оба до
`starter` перед показом.

Бесплатная база Render живёт ограниченное время и удаляется вместе со всеми
строками. Перед тем как класть туда данные платящего клиента, проверьте
текущие условия тарифа.

## Перед началом

**Cloudflare R2.** Единственное место, где проект работает с байтами видео.
Без него API отвечает 503 на загрузку, а воркер отказывается стартовать — то
есть ИИ-монтажёра просто нет. Нужен бакет и S3-совместимый ключ; запишите
`STORAGE_ENDPOINT`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`,
`STORAGE_SECRET_ACCESS_KEY`.

**Ключ OpenAI** с ненулевым балансом. Пустой счёт — это не «медленно», это
каждое задание падает с `transcription_quota_exhausted`.

**Ключи для push.** Сгенерировать заранее:

    node -e "console.log(JSON.stringify(require('web-push').generateVAPIDKeys()))"

Их нельзя оставить на автогенерацию: файловая система контейнера эфемерна,
ключ пересоздался бы на каждом деплое и молча сломал все подписки браузеров.

## Шаги

**1. Создать Blueprint** из репозитория. Render поднимет базу, API, воркер и
фронтенд. Первый деплой API упадёт или будет нездоров — секретов ещё нет, это
ожидаемо.

**2. Дать API его секреты:** `OPENAI_API_KEY`, четыре `STORAGE_*`,
`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`. `DATABASE_URL` и `SESSION_SECRET`
Render проставил сам.

**3. Дождаться, пока API поднимется.** При первом старте на пустую базу он сам
применяет `src/schema.sql` — отдельного шага миграции нет. Проверить:
`/health` отвечает.

**4. Создать роль воркера.** Подключиться к `sonar-db` и выполнить
`src/worker-role.sql`, подставив пароль. Роль видит `video_edit_jobs`,
`notifications` и `push_subscriptions` — и ничего больше.

Это не перестраховка. Воркер скармливает ffmpeg файлы, загруженные
посторонними людьми, а ffmpeg разбирает недоверенные контейнеры. Если его
скомпрометируют крафченым видео, с ролью API злоумышленник дотянулся бы до
хэшей паролей.

**5. Настроить воркер:** `DATABASE_URL` — строка подключения **под ролью из
шага 4**, не та, что у API. `SESSION_SECRET` — **то же самое значение, что у
API**: API подписывает ссылки на медиа, воркер их проверяет, и два разных
секрета отвергнут подписи друг друга. Плюс `OPENAI_API_KEY` и `STORAGE_*`.

`GOOGLE_SPEECH_API_KEY` оставить пустым. Казахский и смешанную речь обрабатывает
ансамбль в `transcriptEnsemble.ts`; если задать ключ, распознавать молча начнёт
Google.

**6. Настроить фронтенд:** `API_ORIGIN` — полный адрес `sonar-api` со схемой
(`https://…`), `NEXT_PUBLIC_SITE_URL` — собственный адрес фронтенда.

**7. Замкнуть CORS:** в API выставить `CORS_ORIGIN` в адрес фронтенда и
передеплоить.

**8. Проверить живьём.** Открыть фронтенд, войти, загрузить короткое видео,
запустить ИИ-монтаж. Если задание висит в `processing` и стадия не меняется —
воркер не поднялся; смотреть его логи, а не логи API.

## Что ломается чаще всего

**Задания стоят, воркер перезапускается.** Почти всегда `SESSION_SECRET` не
задан или отличается от API. Воркер не обслуживает HTTP, но выводит из этого
значения ключ подписи ссылок на медиа ещё при загрузке модуля — без него
процесс падает до первого опроса очереди.

**Загрузка отвечает 503.** Не заданы `STORAGE_*` у API. Это намеренное
поведение: до появления бакета уровень 3 недоступен, а не наполовину работает.

**Вход не держится.** `CORS_ORIGIN` не совпадает с адресом фронтенда. Браузер
обращается только к фронтенду, тот проксирует `/api` — на этом стоит
`SameSite=Lax` у сессионной cookie.

**Сборка образа воркера падает** на проверке Montserrat или `bd.rnnn`. Так и
задумано: без шрифта libass молча подставит другой, без модели «убрать шум»
молча ничего не сделает. Лучше уронить сборку, чем выкатить тихо сломанное.
