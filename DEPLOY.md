# Выкатка Sonar на Render

Для того, кто проводит деплой. Порядок шагов важен: несколько значений
существуют только после того, как создан сервис, который их порождает, и
поставить их заранее нельзя.

`render.yaml` создаёт одну вещь: API `sonar-api`, на бесплатном тарифе.

Остальное живёт снаружи. База — **Neon**. Фронтенд — **Vercel**. Воркер рендера
в блюпринте **закомментирован**, потому что он платный, и пока запускается на
своей машине — см. раздел ниже.

Всё, помеченное `sync: false`, вводится руками.

## Чего это стоит

Сейчас — ничего. Всё, что создаёт этот блюпринт, на бесплатных тарифах, и
фронтенд на Vercel тоже.

Расплата за это в двух местах. **Воркера на бесплатном плане у Render не
бывает** — видео кодируется процессором, и такую нагрузку бесплатные инстансы
не несут; поэтому он пока на своей машине. И **API на free-плане засыпает** без
нагрузки: первый запрос после паузы ждёт холодный старт, что для показа клиенту
плохо — поднимите до `starter` перед демонстрацией.

**База — в Neon, а не в Render.** Бесплатная база Render живёт ограниченное
время и удаляется вместе со всеми строками; бесплатный тариф Neon не сгорает.
Регион Neon берите европейский, под стать `frankfurt` у сервисов здесь: запросы
делает API, и держать базу за океаном от него незачем.

## Перед началом

**Cloudflare R2.** Единственное место, где проект работает с байтами видео.
Без него API отвечает 503 на загрузку, а воркер отказывается стартовать — то
есть ИИ-монтажёра просто нет. Нужен бакет и S3-совместимый ключ; запишите
`STORAGE_ENDPOINT`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`,
`STORAGE_SECRET_ACCESS_KEY`.

**Ключ OpenAI** с ненулевым балансом. Пустой счёт — это не «медленно», это
каждое задание падает с `transcription_quota_exhausted`.

**Ключи для push.** Сгенерировать заранее:

    node -e "console.log(JSON.stringify(require('web-push').generateVAPIDKeys()))"

Их нельзя оставить на автогенерацию: файловая система контейнера эфемерна,
ключ пересоздался бы на каждом деплое и молча сломал все подписки браузеров.

## Шаги

**0. Завести базу в Neon**, регион — Европа. Скопировать строку подключения;
она понадобится на следующем шаге. Оставьте в ней `sslmode=require`.

**1. Создать Blueprint** из репозитория. Render поднимет API. Первый деплой
упадёт или будет нездоров — секретов ещё нет, это ожидаемо.

**2. Дать API его секреты:** `DATABASE_URL` из шага 0, `OPENAI_API_KEY`,
четыре `STORAGE_*`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`. `SESSION_SECRET`
Render сгенерировал сам.

Плюс одно из двух — кто может завести аккаунт:

- **`SIGNUP_MODE=open`** — регистрируется кто угодно, без кода. Ровно это
  слово, ничего другое не подойдёт.
- **`SIGNUP_INVITE_CODE`** — код, который вводят приглашённые. Форма сама
  спросит у API, показывать поле или нет.

**Не задать ни одну значит закрыть регистрацию, а не открыть.** В продакшне
незаданные переменные запирают вход. Это намеренно: пустая переменная почти
всегда забытая, а не решение пустить в систему всех. Открыть можно только
осознанно набранным словом. API пишет в лог при старте, в каком он состоянии.

Пока открыто — **потолок ущерба равен остатку на счёте OpenAI**. Держите
баланс небольшим и не включайте автопополнение: оно этот потолок снимает.

`ADMIN_BOOTSTRAP_SECRET` нужен, только если кто-то выдаёт ключи к API напрямую
через `POST /api/tenants`. Обычный вход в продукт этот путь не использует —
оставьте пустым.

**3. Дождаться, пока API поднимется.** При первом старте на пустую базу он сам
применяет `src/schema.sql` — отдельного шага миграции нет. Проверить:
`/health` отвечает.

**4. Создать роль воркера.** Подключиться к базе в Neon и выполнить
`src/worker-role.sql`, подставив пароль. Роль видит `video_edit_jobs`,
`notifications` и `push_subscriptions` — и ничего больше.

Это не перестраховка. Воркер скармливает ffmpeg файлы, загруженные
посторонними людьми, а ffmpeg разбирает недоверенные контейнеры. Если его
скомпрометируют крафченым видео, с ролью API злоумышленник дотянулся бы до
хэшей паролей.

**5. Настроить воркер** — см. «Воркер на своей машине» ниже, пока он не
оплачен в облаке. Где бы он ни стоял, два значения обязательны и их путают
чаще всего: `DATABASE_URL` — **под ролью из шага 4**, не под ролью API, а
`SESSION_SECRET` — **то же самое значение, что у API**. API подписывает ссылки
на медиа, воркер их проверяет, и два разных секрета отвергнут подписи друг
друга.

`GOOGLE_SPEECH_API_KEY` оставить пустым. Казахский и смешанную речь обрабатывает
ансамбль в `transcriptEnsemble.ts`; если задать ключ, распознавать молча начнёт
Google.

**6. Выкатить фронтенд на Vercel** из папки `frontend`. Переменные:
`API_ORIGIN` — полный адрес `sonar-api` со схемой (`https://…`), и
`NEXT_PUBLIC_SITE_URL` — собственный адрес на Vercel.

`API_ORIGIN` намеренно без префикса `NEXT_PUBLIC_`: это адрес, на который Next
проксирует запросы на сервере, браузер его не видит и обращается только к
домену Vercel. На этом стоит `SameSite=Lax` у сессионной cookie.

Заголовки безопасности страниц лежат в `frontend/vercel.json` и применяются
сами. Два решения там стоит знать.

`Strict-Transport-Security` выставлен **без** `includeSubDomains`: на своём
домене это правило распространилось бы на все поддомены разом, и любой из них,
работающий по http, стал бы недоступен. Когда все поддомены будут на https —
можно усилить.

Полноценного `Content-Security-Policy` пока нет, только `frame-ancestors`
(защита от подмены кликов). Полная политика должна разрешать домен R2, откуда
браузер тянет готовые ролики и постеры, а бакета ещё не существует — политика,
написанная вслепую, сломала бы воспроизведение видео. Дописать после шага с R2
и проверить на живой странице.

**7. Замкнуть CORS:** в API выставить `CORS_ORIGIN` в адрес фронтенда и
передеплоить.

**8. Проверить живьём.** Открыть фронтенд, зарегистрироваться с кодом
приглашения из шага 2, загрузить короткое видео, запустить ИИ-монтаж. Если задание висит в `processing` и стадия не меняется —
воркер не поднялся; смотреть его логи, а не логи API.

## Что ломается чаще всего

**Задания стоят, воркер перезапускается.** Почти всегда `SESSION_SECRET` не
задан или отличается от API. Воркер не обслуживает HTTP, но выводит из этого
значения ключ подписи ссылок на медиа ещё при загрузке модуля — без него
процесс падает до первого опроса очереди.

**Загрузка отвечает 503.** Не заданы `STORAGE_*` у API. Это намеренное
поведение: до появления бакета уровень 3 недоступен, а не наполовину работает.

**Вход не держится.** `CORS_ORIGIN` не совпадает с адресом фронтенда. Браузер
обращается только к фронтенду, тот проксирует `/api` — на этом стоит
`SameSite=Lax` у сессионной cookie.

**Регистрация отвечает «закрыта».** Не задан ни `SIGNUP_INVITE_CODE`, ни
`SIGNUP_MODE=open`. Это не поломка, а то, как оно устроено: незаданные
переменные запирают вход, а не открывают его. API написал об этом в лог при
старте.

**Сборка образа воркера падает** на проверке Montserrat или `bd.rnnn`. Так и
задумано: без шрифта libass молча подставит другой, без модели «убрать шум»
молча ничего не сделает. Лучше уронить сборку, чем выкатить тихо сломанное.

## Воркер на своей машине

Пока воркер не оплачен в облаке, он запускается локально против продовой
базы. Это работает, потому что он не обслуживает HTTP и не принимает входящих
соединений вообще — он только сам опрашивает базу, так что ему достаточно
исходящего интернета.

В отдельном файле окружения (не в `.env` разработки, чтобы не перепутать базы):

    DATABASE_URL=<строка подключения под ролью воркера, не под ролью API>
    SESSION_SECRET=<то же значение, что у sonar-api>
    OPENAI_API_KEY=<...>
    STORAGE_ENDPOINT=<...>
    STORAGE_BUCKET=<...>
    STORAGE_REGION=auto
    STORAGE_ACCESS_KEY_ID=<...>
    STORAGE_SECRET_ACCESS_KEY=<...>

Запуск: `npm run worker`.

Что это означает на практике:

- **Рендер идёт, только пока машина включена.** Задания не теряются — они
  лежат в базе и будут подобраны, когда воркер вернётся, — но клиент всё это
  время видит «в обработке». Обещайте тестировщикам окно, а не круглосуточную
  работу.
- **Нужно свободное место на диске.** Рендер одновременно держит исходник,
  извлечённое аудио и результат.
- **На машине оказываются боевые ключи.** Включите шифрование диска, ограничьте
  доступ к базе по IP, и заведите для воркера отдельный ключ R2, а не тот же,
  что у API. Роль воркера в базе и так урезанная, но это ограничивает ущерб,
  а не отменяет его.

Перенос в облако: раскомментировать сервис в `render.yaml`, снять с каждой
строки один префикс `# `, закоммитить.
